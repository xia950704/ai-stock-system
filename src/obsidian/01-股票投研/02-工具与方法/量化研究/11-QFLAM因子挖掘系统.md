# QFLAM：Andrej Karpathy范式在量化因子挖掘中的落地

> 灵感来自OpenAI创始成员Andrej Karpathy（现加入Anthropic）的**auto-research**项目，将其范式完整复刻到量化因子挖掘中，创建了**QFLAM**系统。

---

## 一、思想源头：Karpathy的Auto-Research

一个极简但极具颠覆性的范式：

### 三大组件
| 组件 | 定义 | AI能改？ |
|------|------|---------|
| **固定评分标准** | 什么是"好"的实验结果 | ❌ AI不可修改 |
| **可修改的核心代码** | 模型结构、超参数等 | ✅ AI唯一能改 |
| **研究规程(prompt.md)** | 研究方向、已知有效方法、要避开的坑 | 人类通过修改此文引导AI |

### 惊人效果
- AI自主运行一晚上，进行了 **100多次**实验
- 将验证损失降低
- 发现的最优改进方案**直接迁移到更大模型**训练上 → **模型效率提升11%**
- 相当于：**一张GPU + 几天时间 = 研究员数月工作量**

---

## 二、范式迁移：QFLAM的三大量化组件

### 1. 固定评分标准
综合评价体系（AI不可修改）：

| 指标 | 含义 |
|------|------|
| **Rank IC** | 选股排序准不准 |
| **IR（信息比率）** | 排序稳不稳 |
| **覆盖率** | — |
| 相关性检查 | 强制检查与现有因子的相关性 |
| 总分 | 以上加权 |

### 2. 可修改的因子代码
- AI每轮修改：**生成因子值的Python代码**
- 输入：行情数据
- 输出：股票得分
- 代码生成后→ **沙箱安全执行** → 评分通过才能进入因子池

### 3. 研究规程（prompt.md）
- 定义实验流程、已有的优秀初始因子
- 人类可随时修改以调整AI探索方向

---

## 三、解决因子挖掘的特有问题

### 多样性与记忆
| 问题 | 方案 |
|------|------|
| AI反复挖掘同一类高相关因子 | **多样性门控**：高相关性因子直接淘汰 |
| 长上下文导致早期经验被遗忘 | **独立编排器**管理"研究记忆"，每轮结束强制AI总结分析成败原因 |

### 防范数据泄露（沙箱机制）
| 限制 | 说明 |
|------|------|
| 禁止IO操作 | ❌ 不能读写文件 |
| 白名单计算库 | ✅ 仅允许使用指定库 |
| 超时熔断 | ⏱ 超时自动终止 |

## 四、实战成果

| 指标 | 值 |
|------|-----|
| 运行轮数 | **588轮** |
| 成功生成因子 | **236个** |
| 最终存活因子 | **50个** |
| 淘汰率 | **>80%** |
| 全部API成本（DeepSeek） | **不到1块钱** |

---

## 五、核心启示

1. **AI生成+严格评价是可行范式** — 80%淘汰率证明了"绑定生成与评价"的必要性
2. **成本可极低** — DeepSeek API 588轮<1元
3. **人的角色从"挖矿"转向"设计矿场规则"** — 定义评分标准和研究规程，而非亲自写因子公式
4. **沙箱是代码化因子的刚需** — 没有沙箱的因子挖掘系统不安全

## 六、与调研结果对照（[[01-股票投研/02-工具与方法/量化研究/10-AI因子挖掘调研.md]]）

| 第十二期理论（四重关卡） | QFLAM工程实现 |
|-------------------------|--------------|
| 1. 给出明确边界 | 固定评分标准(Rank IC/IR等) + 研究规程(prompt.md) |
| 2. 绑定"生成"与"评价" | AI生成Python因子代码 → 沙箱执行 → 严格评分 → 淘汰 |
| 3. 建立"可解释的演化" | 多样性门控（高相关性淘汰）+ 编排器管理研究记忆 |
| 4. 沉淀"研究记忆" | 每轮结束强制AI写研究总结，分析成败原因 |
