## 三、回放可行性判断

### 3.1 可完整回放的日期范围

**价格层：2020-01-02 ~ 2026-10-20（1645 个交易日）**
- 来源：duckdb daily_kline
- 数据质量：OHLCV 完整，无缺失

**全引擎层（含锚价/排名/实时快照）：仅 2 个日期**
- 2026-09-23（锚价快照 + 实时快照）
- 2026-10-20（排名快照 + 实时快照）

### 3.2 不可回放的数据源及原因

| 数据源 | 不可回放原因 |
|--------|-------------|
| 锚价快照 | 仅 1 个历史文件（2026-09-23），其余日期无快照 |
| 排名快照 | 仅 1 个当前文件（2026-10-20），无历史版本 |
| 实时价格 | 仅 2 个文件（2026-09-23, 2026-10-20） |
| JEV | 无真实历史输出（128 条全为 2026-10-20 mock） |
| Search API | 无历史检索记录 |
| 投资组合 | 无历史快照 |
| 研发面 | 仅当前内容 + git history（69 commits，非连续） |

### 3.3 回放模式

**模式 A：价格层回放（1645 天）**
- 输入：仅 K 线价格（真实历史数据）
- 输出：价格层指标（当前价、技术面）
- 局限：锚价/排名/JEV/Search 标记为 unavailable
- 行动状态：多数为 INSUFFICIENT_EVIDENCE（证据不足时拒绝判断）

**模式 B：全引擎回放（2 天）**
- 输入：锚价快照 + 排名 + 实时价格
- 输出：完整研判（大盘 + 个股 + JEV/Search 标记）
- 适用：验证引擎端到端行为

### 3.4 偏差与局限

1. 锚价快照稀疏：仅 2 个日期，无法评估锚价策略的跨期表现
2. 排名快照缺失：技术面评分无法参与历史判断
3. JEV/Search 无历史记录：无法评估外部模型的历史表现
4. PE 快照非连续：32 个日期但间隔不均，无法用于逐日回放
5. Obsidian git history 不连续：69 commits 覆盖 2026-06-15 ~ 2026-10-17，但非每日快照
6. 配对交易子系统报告：50 份历史报告来自不同系统，不与 P3 每日引擎直接可比

### 3.5 最低条件判断

具备开展历史表现评估的最低条件：
- 价格数据覆盖充分（1645 天）
- 反前视机制可验证（lookahead_check 通过）
- 降级行为可测试（INSUFFICIENT_EVIDENCE 正确触发）
- 重复运行一致性可验证

不具备的条件：
- 锚价策略的跨期表现无法评估（快照不足）
- 完整引擎的逐日表现无法评估
- JEV/Search 的历史效果无法评估

**结论：可进行框架验证和价格层评估，不可宣称完整历史回测。**
